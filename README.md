# Analysis & QA Orchestrator — web-презентация

Статический прототип презентации на HTML, CSS и vanilla JavaScript. Backend и сборка не требуются.

## Запуск

Откройте `index.html` напрямую в браузере или запустите простой локальный сервер:

```powershell
python -m http.server 8080
```

После этого откройте `http://localhost:8080/`.

## GitHub Pages

Собрать чистый публикационный пакет локально:

```powershell
node scripts/build-pages.js
```

Результат создаётся в `dist-pages/`. Для локальной проверки используйте:

```powershell
python -m http.server 8080 --directory dist-pages
```

и откройте `http://localhost:8080/`. В deploy входят только runtime HTML/CSS/JS/data, используемые изображения, 27 кадров SORT-1998 и OGG-файлы из `data/audio-manifest.js`. Reference-материалы, генераторы, debug-инструменты, speed samples и legacy-аудио намеренно исключаются.

Рекомендуемая публикация — GitHub Actions → GitHub Pages через `.github/workflows/pages.yml`. В настройках репозитория выберите **Settings → Pages → Source: GitHub Actions**, затем отправьте изменения в ветку `main` или запустите workflow вручную. Для публикации презентации секреты не требуются.

## Управление

- `←` / `→` — предыдущий / следующий экран;
- `Space` — следующий экран;
- меню «Экраны» — переход к конкретному основному экрану;
- «Технические детали» — отдельный резервный экран, не входящий в основной flow;
- кнопка `↗` — полноэкранный режим.

Основной контент находится в `data/slides.js`, оформление — в `css/presentation.css`, навигация — в `js/presentation.js`.

## Native workflow (Slice 2.5)

Экран 4 строится из `PRESENTATION_DATA.workflow`: группы, узлы, стабильные ID и `data-sync-key` находятся в data model. Карточки создаются как HTML, а направленные связи и возврат remediation loop - как масштабируемые inline SVG. По умолчанию виден полный маршрут; выбор этапа создаёт увеличенный native focus из тех же данных, повторный выбор, Escape или кнопка сброса возвращают обзор. PNG не участвует в renderer workflow.

Данные 28 правил находятся в `data/rules.js`. Ссылка на обсуждение задаётся полем `discussion.url` в `data/slides.js`; пока URL неизвестен, кнопка остаётся неактивной.

## Подготовка озвучки (Slice 3A.1)

`data/tts.js` — единый источник данных будущей озвучки. Transcript экранов 1–10 дословно соответствует актуальному сценарию `reference/presentation/преза тексты.txt` после нормализации пробелов. Начиная со Slice 3B.1, `ttsText` является отдельной автономной закадровой версией: в ней нет привязки к живому докладчику, а смысловые сокращения раскрыты голосом. Факты, примеры, порядок и детализация live-сценария сохранены. Для каждого основного экрана (`slide-01` … `slide-10`, `questions`) и технического экрана `tech` модель задаёт:

- `transcript` — текст расшифровки для пользовательского интерфейса;
- `ttsText` — нейтральный автономный рассказ для синтеза речи;
- `audioSrc: null` и `autoplayDuration: null` — зарезервированные поля Slice 3B;
- `syncMarkers` — логические привязки к существующим элементам интерфейса без временных меток;
- `segments` — отдельные фрагменты интерактивного сценария, если они нужны экрану.

После загрузки `data/tts.js` присоединяет эти поля к существующим объектам `PRESENTATION_DATA.slides` и `techMeta`. Параллельной копии сценария в `data/slides.js` нет. Уже существующий скрытый контейнер `#transcript-panel` получает transcript текущего экрана; отдельный пользовательский переключатель на этом этапе не добавлялся.

Экран 4 разбит на восемь сегментов по стабильным ID `wf-stage-1` … `wf-stage-7`, включая `wf-stage-5a`. Экраны 5, 6 и 10 содержат логические markers для интерактивных блоков. Экран 8 содержит только вступление; семь сегментов будущего SORT-1998 demo зарезервированы с `null`-текстами. Технический экран исключён из `autoplaySlideIds` и дополнительно помечен `autoplay: false`.

Централизованный словарь display/spoken форм находится в `data/pronunciation.js`. Это единственный источник фонетической адаптации: ручные spoken-подстановки в `ttsText` не используются, а видимый текст интерфейса не меняется. Варианты произношения рассчитаны на последующую проверку и корректировку после выбора реального TTS-голоса.

Точную сверку данных со сценарием можно повторить командой:

```powershell
node scripts/validate-tts.js
```

Проверка сравнивает transcript экранов 1–10 с reference-файлом после нормализации whitespace. Автономный `ttsText` проверяется отдельно: он должен быть непустым, не содержать конструкций первого лица живого докладчика и запрещённых смысловых сокращений. Для экранов 7 и 10 дополнительно проверяются ключевые смысловые якоря, а для экранов 4, 5, 6 и 10 — целостность segment ttsText. Также контролируются обязательные pronunciation entries и отсутствие реальных timing.

Следующий TTS sample должен использовать мужской голос. Конкретный voice в Slice 3B.1 не выбран. Требуемый профиль: спокойная, деловая, естественная русская речь без рекламной или чрезмерно эмоциональной интонации, комфортная для 10–15 минут прослушивания. Это требование также зафиксировано в `PRESENTATION_TTS.voiceProfile`.

На этапе Slice 3A.1 аудиофайлы и playback сознательно не реализовывались. Они подключены отдельным слоем в Slice 3B.

## Audio layer (Slice 3B)

Архитектура воспроизведения подготовлена независимо от конкретного TTS-провайдера:

- `data/audio-manifest.js` — единственный источник путей к аудио, порядка сегментов и autoplay eligibility;
- `js/audio-controller.js` — загрузка, play/pause/resume, replay, mute, последовательность сегментов, autoplay и безопасная обработка ошибок;
- `data/tts.js` — неизменяемый источник согласованного текста и сегментов;
- `data/pronunciation.js` — единственный источник фонетических замен перед генерацией;
- `scripts/generate-audio.js` — единая production-команда Yandex SpeechKit;
- `assets/audio/` — место для production-аудио и отдельно именованных тестовых sample.

В нижней панели доступны воспроизведение/пауза, повтор, mute, transcript и переключатель «Авто». Кнопка «Начать презентацию» является первым пользовательским жестом, необходимым браузеру для разрешения звука. В ручном режиме переходы между экранами не запускают звук автоматически. При включённом «Авто» окончание всех дорожек экрана переводит презентацию к следующему основному экрану и запускает его аудио. Технический экран в этот flow не входит.

Transcript скрыт по умолчанию и открывается кнопкой «Текст». Drawer показывает только согласованный `transcript`, не `ttsText` и не фонетические подстановки. Состояния mute, autoplay и transcript сохраняются в `sessionStorage`; позиция воспроизведения не сохраняется.

Экран 4 использует intro и восемь последовательных stage-файлов со stable keys `wf-stage-1` … `wf-stage-7`, включая `wf-stage-5a`. Экраны 5, 6 и 10 также разбиты на последовательные смысловые файлы. Начало файла является точной границей sync, поэтому фиктивные timestamps не нужны. На экране 10 окно правил автоматически не открывается. Экран 8 содержит только intro; SORT-1998 demo не реализовано.

Если файл отсутствует, формат не поддержан или playback прерван ошибкой, controller выключает autoplay, оставляет навигацию рабочей и показывает ненавязчивое сообщение.

### Production-генерация Yandex SpeechKit

Проверки:

```powershell
node scripts/validate-tts.js
node scripts/validate-pronunciation.js
node scripts/validate-audio.js
```

Проверить production queue без API-вызовов:

```powershell
node scripts/generate-audio.js --dry-run
```

Production-параметры едины для всего corpus:

- provider: Yandex SpeechKit REST v3;
- voice: `filipp`;
- role: не передаётся;
- speed: `1.25`;
- format: `OGG_OPUS`;
- destination: `assets/audio/`.

Production-аудио синтезировано голосом `filipp` без role, со скоростью SpeechKit `1.25` и в формате `OGG_OPUS`. Реальные длительности файлов записаны в единственном manifest `data/audio-manifest.js` и проверяются по метаданным OGG Opus.

В браузере доступны скорости `0.8×`, `0.9×`, `1.0×`, `1.1×` и `1.2×`. Значение `1.0×` воспроизводит исходную production-дорожку без дополнительного изменения скорости. Выбор применяется через `HTMLAudioElement.playbackRate` сразу к текущей дорожке без перезапуска, ко всем следующим дорожкам и сохраняется в `sessionStorage` до конца сессии.

В Manual Mode навигация свободна, переход останавливает текущую дорожку, сбрасывает её позицию и очищает sync state; новый экран сам не запускается. Включение «Авто» на любом экране сбрасывает именно этот экран в начальное состояние, запускает его озвучку с начала и затем ведёт основной flow до экрана 11. Выключение «Авто» оставляет текущий экран открытым и ставит аудио на паузу. Technical Details исключён из Auto.

В Auto доступны только Play/Pause и кнопка «Авто». Навигация, меню экранов, Technical Details, Replay, Mute, transcript, fullscreen и выбор скорости остаются видимыми, но блокируются с подсказкой. Auto использует последнюю скорость, выбранную в Manual Mode. Во время воспроизведения интерактив текущего экрана управляется синхронизацией; на паузе пользователь может исследовать текущий экран, а Resume восстанавливает состояние активного аудиосегмента.

Transcript drawer стабильно показывает полный согласованный transcript текущего экрана, включая сегментированные экраны. Он не показывает `ttsText`, provider-bound pronunciation или внутренние sync keys. Экран 4 синхронизируется по пяти существующим увеличенным разделам: документы, требования, проверка аналитики, исправление БА/СА и тестовое покрытие; после последнего сегмента возвращается полная схема. Экраны 5, 6 и 10 сохраняют прежнюю синхронизацию, окно правил автоматически не открывается. На экране 8 воспроизводится только intro, а SORT-1998 demo остаётся нереализованным.

После изменения сегментации экрана 4 необходимо локально перегенерировать только шесть его файлов:

```powershell
node scripts/generate-audio.js "--tracks=slide-04-intro,slide-04-section-01,slide-04-section-02,slide-04-section-03,slide-04-section-04,slide-04-section-05"
```

До этой генерации manifest хранит `duration: null` для шести ожидающих файлов; вымышленные длительности не используются. После генерации реальные длительности следует зафиксировать отдельной post-generation проверкой.

Экран 5 использует реальные decision-state существующего интерфейса: neutral, Accept/Exclude требования и Exclude/Accept проблемы аналитики. Auto вызывает ту же функцию выбора, что и ручные кнопки, а Resume восстанавливает state активного сегмента. Для этой синхронизации требуются пять новых файлов:

```powershell
node scripts/generate-audio.js "--tracks=slide-05-intro,slide-05-requirement-accept,slide-05-requirement-exclude,slide-05-problem-exclude,slide-05-problem-accept"
```

До локальной генерации эти пять дорожек также имеют `duration: null`. Старые `slide-05/requirement.ogg` и `slide-05/finding.ogg` больше не входят в manifest.

Экран 6 начинается с нейтрального командного intro, затем Auto последовательно активирует `business → sdm → ba-sa → developer → qa → support`. Каждый role-state имеет законченный самостоятельный фрагмент. Для нового intro и изменённых business/BA-SA нужны только три файла:

```powershell
node scripts/generate-audio.js "--tracks=slide-06-intro,slide-06-business,slide-06-ba-sa"
```

Новые пути — `slide-06/intro.ogg`, `slide-06/business-v2.ogg` и `slide-06/ba-sa-v2.ogg`; прежние `business.ogg` и `ba-sa.ogg` больше не входят в manifest. Дорожки SDM, developer, QA и support не меняются.

На экране 10 Auto открывает существующую модалку правил на сегменте `human-approval`, где озвучивается сформированный набор правил. В Auto модалка пассивна даже на Pause: закрытие, прокрутка и внутренние действия заблокированы. При переходе к следующему сегменту она автоматически закрывается. В Manual Mode модалка остаётся полностью интерактивной. После точечной правки текста нужно локально обновить две дорожки:

```powershell
node scripts/generate-audio.js "--tracks=slide-10-origin,slide-10-approval"
```

Новые пути — `slide-10/rules-origin-v2.ogg` и `slide-10/human-approval-v2.ogg`; прежние версии этих двух файлов больше не входят в manifest.

Ключ читается только из `YANDEX_SPEECHKIT_API_KEY`. После задания переменной в текущей PowerShell-сессии запустите одну команду:

```powershell
node scripts/generate-audio.js
```

Скрипт сам запускает три validation, применяет централизованный pronunciation preprocessing и генерирует 29 manifest tracks. Валидные существующие production-файлы пропускаются, поэтому прерванный запуск можно безопасно продолжить. Ошибки выводятся вместе с ID дорожки, а в конце печатается количество созданных, пропущенных и неуспешных файлов. Sample-файлы `slide-01-speed-*.ogg` и будущие `demo-*` сегменты SORT-1998 в production queue не входят. Технический экран генерируется, но остаётся исключённым из autoplay.

Для точечной принудительной перегенерации уже существующих дорожек передайте их manifest IDs через `--tracks`. Например: `node scripts/generate-audio.js "--tracks=slide-01,slide-02"`. В этом режиме остальные production-файлы не затрагиваются, а выбранные дорожки генерируются заново.
